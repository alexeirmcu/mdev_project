# Specifications: align-domain-with-requirements

This document specifies the domain changes required to align the system with the updated trip planning requirements.

## SelectedAttraction Specification

### Purpose
The `SelectedAttraction` represents an attraction that has been explicitly selected for a trip, decoupling the attraction's static data from the trip-specific selection metadata.

### Requirements

#### Requirement: SelectedAttraction Validation
The system MUST validate the attraction during the creation of a `SelectedAttraction`.

**Scenario: Successful Creation**
- GIVEN a valid `Attraction` object
- WHEN a `SelectedAttraction` is created using this attraction
- THEN the `SelectedAttraction` should be successfully instantiated
- AND the internal attraction reference should be set

**Scenario: Null Attraction Prevention**
- GIVEN a null reference instead of an `Attraction`
- WHEN attempting to create a `SelectedAttraction`
- THEN the system MUST throw an `ArgumentNullException`

#### Requirement: SelectedAttraction Equality
Equality for `SelectedAttraction` MUST be determined by the identity of the underlying attraction.

**Scenario: Equality based on ID**
- GIVEN two `SelectedAttraction` instances referencing the same `Attraction` ID
- WHEN comparing the two instances for equality
- THEN they MUST be considered equal

**Scenario: Inequality for different attractions**
- GIVEN two `SelectedAttraction` instances referencing different `Attraction` IDs
- WHEN comparing the two instances for equality
- THEN they MUST NOT be considered equal

## Trip Specification

### Purpose
The `Trip` entity manages the overall state of a trip, including the set of attractions the user wants to visit and global configuration.

### Requirements

#### Requirement: Selected Attractions Management
The `Trip` MUST replace the `OriginalMustSees` list with a collection of `SelectedAttraction` objects.

**Scenario: Replace OriginalMustSees**
- GIVEN a `Trip` instance
- WHEN accessing the list of mandatory attractions
- THEN the system MUST return a collection of `SelectedAttraction` (not `Attraction`)

#### Requirement: Dynamic Update of Selected Attractions
The `Trip` MUST allow the dynamic addition and removal of `SelectedAttraction` objects.

**Scenario: Adding a Selected Attraction**
- GIVEN a `Trip` with an empty list of selected attractions
- WHEN a `SelectedAttraction` is added
- THEN the list MUST contain exactly one `SelectedAttraction`

**Scenario: Removing a Selected Attraction**
- GIVEN a `Trip` with one `SelectedAttraction`
- WHEN that attraction is removed
- THEN the list MUST be empty

#### Requirement: Global Start Time Configuration
The `Trip` SHOULD maintain a default start time configuration that serves as the baseline for individual `DayPlan` objects.

**Scenario: Default Global Start Time**
- GIVEN a new `Trip` instance
- WHEN querying the global start time
- THEN it SHOULD return the default system start time (e.g., 09:00)

## DayPlan Specification

### Purpose
The `DayPlan` defines the schedule for a single day of the trip.

### Requirements

#### Requirement: Default Day Start Time
A `DayPlan` MUST be initialized with a default `StartTime` of 09:00.

**Scenario: Initialization Default**
- GIVEN a new `DayPlan` instance
- WHEN the `StartTime` property is accessed immediately after creation
- THEN it MUST be equal to `TimeOnly.Parse("09:00")`

#### Requirement: Editable Day Start Time
The `StartTime` of a `DayPlan` MUST be editable by the user or the planning system.

**Scenario: Updating Start Time**
- GIVEN a `DayPlan` with a `StartTime` of 09:00
- WHEN the `StartTime` is updated to 10:00
- THEN the `StartTime` MUST be 10:00
- AND any subsequent calculations for that day MUST use 10:00 as the baseline

---

## ActivityNode Specification

### Purpose
The `ActivityNode` represents a specific activity or slot within a `DayPlan`.

### Requirements

#### Requirement: Default Priority for Auto-generated Nodes
Nodes that are created as fillers or auto-generated by the system MUST default to `Priority.Medium`.

**Scenario: Filler Node Default Priority**
- GIVEN the system is generating a filler `ActivityNode`
- WHEN the node is instantiated without an explicit priority
- THEN its `Priority` MUST be set to `Priority.Medium`

#### Requirement: Completion State Tracking
The `ActivityNode` MUST maintain a state indicating whether the activity has been completed.

**Scenario: Checking Completed State**
- GIVEN an `ActivityNode` that has not been marked as completed
- WHEN querying its `IsCompleted` status
- THEN it MUST return `false`

**Scenario: Marking Activity as Completed**
- GIVEN an `ActivityNode`
- WHEN the node is marked as completed
- THEN its `IsCompleted` status MUST return `true`
